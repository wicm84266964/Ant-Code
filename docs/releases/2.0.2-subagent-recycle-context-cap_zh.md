# Ant Code v2.0.2：失联子智能体回收与主控上下文上限

发布日期：2026-09-01

这是 2.0 TypeScript 运行时上的小版本修复。Dashboard 回收失联后台子智能体时，不再要求当前进程里还有活的 controller；主控发给模型的工具结果有默认上限，避免广域扫描把下一轮网关请求撑到被上游 HTTP 400 拒收。权限模式 id 不变。本说明处于公开发布候选阶段，不表示 CI、tag 或 GitHub Release 已经完成。

## 对用户工作流的直接变化

- Dashboard 顶部 live chip 的「回收」：当前进程找不到后台子智能体 controller 时，仍把任务写成 `interrupted` 并结束任务组，不再返回冲突且任务文件一直停在 `running`。组回收会取消组内全部子任务。
- 子智能体循环抛错或后台收尾时，若任务还停在非终态，会落盘为 `failed` 或 `interrupted`，避免界面一直显示疑似失联。
- 主控发给模型的工具结果默认截断到 32KB。超过上下文预算时，第 0 轮仍压缩旧会话；之后各轮也会压缩飞行中的过大工具输出，包括最近几条。
- `glob` / `grep` 默认最多 200 条匹配，`list_files` 默认最多 200 项。需要更大的有界切片时，仍可显式提高 `maxMatches` 或 `maxEntries`。

## 配置、数据与安全边界

- 配置格式、session / transcript、凭据存储和网关协议没有迁移。现有 `lab-agent.config.json` 和 `.lab-agent` 会话可继续使用。
- 这次没有改权限模式 id，也没有改网关选择逻辑。
- 默认工具结果上限和枚举条数上限会截断过大的一次扫描结果；这是发给模型的上下文边界，不是删除本地文件。
- 回收失联任务只改本机任务文件；若子智能体其实还在别的进程里跑，不会跨进程强杀。
- 自动化测试不能代表所有私有研究数据、外部模型供应商或现场部署环境都已得到验证。

## 升级与产物位置

需要 Node.js 22.18+。从源码更新：

```sh
git pull
npm ci
npm run verify:install
npm link
ant-code --version
```

`ant-code --version` 应显示 `2.0.2`。若以前 link 过旧安装，需要重新 `npm link`。现有网关配置和会话不必重建。本次没有新的安装包、审计报告或日志目录要求。
