# Ant Code v2.0.19：子任务完整交接报告交给主控，引导思考草稿不再标成中断

发布日期：2026-09-24

本版本是子智能体交接与引导展示小版本。后台唤醒和前台 `agent_run` 会把子任务最终报告整份交给主控，不再只留前几行摘要；点引导后，对话里的思考草稿标成「引导已接管」。写入失败时，发给模型的短回执不再误报已经编辑。候选阶段不提前声称 CI、tag 或 GitHub Release 已经完成。

## 对用户工作流的直接变化

- 后台子任务组完成唤醒主控时，唤醒消息附上每条子任务的完整最终报告（`output`），不再压成约 600 字摘要。主控不必再翻任务 JSON 才能看到 Reviewer 的 findings。
- 前台 `agent_run` 同样把完整交接报告交给主控，不再用 8,000 字头尾截断，也不再误用那 8 行摘要。子任务中间的工具轮次仍留在任务记录里，不会塞进主控上下文。
- Dashboard 点引导后，正在流的思考草稿标成「思考 · 引导已接管」；Esc / Ctrl+C / 引导停止仍标成「已中断 · 非最终回复」。刷新后按落盘前缀区分。
- `write_file` / `edit_file` 失败时，模型可见回执不再同时出现 `ok=false` 和 `edited=true`。覆盖已有文件的成功路径仍报 `edited=true`。

## 配置、数据与安全边界

- 后台唤醒默认上限从 12KB 调整为 96KB，以便一份完整复核报告能进主控。只有报告本身超过该上限才会截断，并标明任务文件路径。
- 不改变权限模式、凭据存储格式或网关配置格式。
- 现有 session 可继续打开，无需重建。
- 自动化测试不能代表所有私有研究数据或每一个外部模型供应商都已验证。

## 升级与产物位置

```sh
npm ci
npm run verify:install
npm link
ant-code --version
```

`ant-code --version` 应显示 `2.0.19`。正在运行的 Dashboard 需要重启并硬刷新浏览器。现有网关配置和 `.lab-agent` 会话不必重建。

## 验证、限制与待完成门禁

- 开发仓类型检查 0 诊断。本轮相关单元测试（wakeup、tool-result-view、Dashboard 引导草稿、write 失败回执）已通过。候选阶段的正式仓 `verify:release`、CI、tag 和 GitHub Release 完成后才会记入发布记录。
- 已知限制：多条子任务同时完成且报告合计超过 96KB 时，靠后的报告仍会截断并指向任务文件。最终结论以正式仓同一提交的 CI 和 Release 门禁为准。
