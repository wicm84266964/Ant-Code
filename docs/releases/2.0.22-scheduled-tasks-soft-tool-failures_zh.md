# Ant Code v2.0.22：定时任务与工具失败轻提示

发布日期：2026-10-17

本版本是 Dashboard 工作流的小版本。工具调用失败不再把前面的思考标成已中断；可以在会话里确认一次定时任务，到点由本机 Dashboard 把保存的提示词再发一轮。候选阶段不提前声称 CI、tag 或 GitHub Release 已经完成。

## 对用户工作流的直接变化

- 写入失败、搜索失败、读取失败、列出 MCP 能力超时这类工具回执，只在对话里留一行收起的提示，例如「搜索代码未成功，本轮继续」。思考过程继续流，运行状态保持运行中。
- 用户停止、引导接管、上游断开，以及整轮请求失败，仍显示已中断或失败。
- 在会话里说明时间和要做的事，确认后会保存一条定时任务。可以只跑一次，例如五分钟后；也可以每天、每周，或按至少 15 分钟的间隔重复。
- 创建确认会先说明：自动任务用完全访问权限运行，到点不再弹出放权。确认后任务才保存。
- 左侧栏可以查看下次时间，并暂停、恢复或删除任务。一次性任务发送后停用。会话正忙或正在 Goal 时，这一轮跳过并稍后重试。

## 配置、数据与安全边界

- 定时任务保存在当前项目的 `.lab-agent/schedules/`。不改变权限模式编号、凭据存储或网关配置格式。
- 到点运行使用完全访问，写文件和命令不再等待逐项批准。创建时的确认就是这次授权。
- 现有 session 可继续打开，无需重建。已经保存的日程会在下一次到点按完全访问运行。
- Dashboard 进程没开时不计时。重新打开后，错过的轮次只补一次。
- 自动化测试不能代表所有私有研究数据或每一个外部模型供应商都已验证。

## 升级与产物位置

```sh
npm ci
npm run verify:install
npm link
ant-code --version
```

`ant-code --version` 应显示 `2.0.22`。正在运行的 Dashboard 需要重启并刷新浏览器。现有网关配置和会话不必重建。

## 验证、限制与待完成门禁

- 开发仓已运行定时任务单元测试和 Dashboard UI 源码约束测试。候选阶段的正式仓 `verify:release`、CI、tag 和 GitHub Release 完成后才会记入发布记录。
- 已知限制：定时任务依赖本机 Dashboard 进程；间隔重复最短 15 分钟；一次性任务最短 1 分钟、最远 7 天。最终结论以正式仓同一提交的 CI 和 Release 门禁为准。
