# Ant Code v2.0.3：发图压缩、模型窗口与并行中断

发布日期：2026-09-02

这是 2.0 TypeScript 运行时上的小版本修复。发图不再把当前轮图片压掉，也不再用图片 base64 误触发两次压缩；切换到更大窗口的模型会抬高本地上下文预算；并行子智能体里有一条中断时，不再把整轮父会话标成黄灯「已中断」。权限模式 id 不变。本说明处于公开发布候选阶段，不表示 CI、tag 或 GitHub Release 已经完成。

## 对用户工作流的直接变化

- 附件图片仍以 `data:<mime>;base64,...` 发给网关（Chat Completions 用 `image_url`，Responses 用 `input_image`）。本地估 token 不再把整段 base64 当文本；历史需要压缩时，当前这一轮的图片或视觉报告仍会发给模型。
- 主模型带视觉时直接看图。主模型只支持文本时，仍先走同一网关的视觉子智能体，主控只收到文字报告。落盘 transcript 仍然只保留脱敏后的图片摘要。
- 从较小窗口模型切到更大窗口模型时，本地 `context.maxTokens` / `maxBytes` 至少抬到新模型的窗口。切到更小窗口时，有效上限仍按较小的那个封顶。
- 并行只读子智能体里，某一次 MCP/工具中断不再把整轮父会话收成「已中断」。点停止（turn AbortSignal）仍然会停掉整轮。MCP 超时记成失败（`MCP_REQUEST_TIMEOUT`），不再当成用户停止。

## 配置、数据与安全边界

- 配置格式、session / transcript、凭据存储和网关协议没有迁移。现有 `lab-agent.config.json` 和 `.lab-agent` 会话可继续使用。
- 这次没有改权限模式 id，也没有改网关选择逻辑。
- 图片像素不会写入 session 文件；历史里只保留 `redacted` 摘要。
- 若有人故意把本地压缩阈值设得比当前模型窗口更小，切换一次更大窗口的模型会被抬上去。
- 自动化测试不能代表所有私有研究数据、外部模型供应商或现场部署环境都已得到验证。

## 升级与产物位置

需要 Node.js 22.18+。从源码更新：

```sh
git pull
npm ci
npm run verify:install
npm link
ant-code --version
```

`ant-code --version` 应显示 `2.0.3`。若以前 link 过旧安装，需要重新 `npm link`。正在跑的 Dashboard 需要重启后才会用到这次修复。现有网关配置和会话不必重建。本次没有新的安装包、审计报告或日志目录要求。
