# Ant Code v2.0.29：源码版安全更新入口，历史 Goal 可可靠停止

发布日期：2026-10-26

本版本为 Dashboard 增加启动版本显示和源码更新按钮，并修复历史会话中 Goal 停止、活动状态及队列权限的边界问题。这是源码版功能与安全性修复候选；尚不表示正式仓 CI、tag 或 GitHub Release 已经完成。

## 对用户工作流的直接变化

- Dashboard 左上角显示当前进程启动时的版本，并提供“更新”入口。独立源码安装可检查当前分支的官方 HTTPS 上游，确认目标后准备依赖，再以 fast-forward 更新并在原项目、原端口重启；端口恢复或版本文字变化本身不算成功，还会核验目标 commit 和新进程身份。
- 更新时动态读取应用、环境、Git/npm 和 Windows 静态系统代理中的真实 HTTP/HTTPS 地址与端口，不扫描端口、不猜常用端口。没有可用配置可手填仅本次代理，或主动允许仅本次直连。Git 与 npm 使用同一路由；代理失败不静默直连、不换镜像、不关闭 TLS 校验。SOCKS、PAC/WPAD 暂不支持。
- 本地修改、无受支持上游、分叉、其他登记的 Dashboard 或正在运行、排队、等待确认及状态不确定的工作会阻止更新。不会强制取消工作、覆盖源码或自动 stash/reset/clean；候选依赖及启动预检失败时旧服务保持不变。
- 即使历史会话所用模型已失效，也能关闭或暂停 Goal，而不必先恢复模型。启动或恢复执行仍要求有效模型，不会擅自换模型。历史“运行中”记录不再冒充当前活动，打开历史 Goal 不会自动启动新任务。
- 停止 Goal 后，尚未开始的用户队列保留原内容，不会沿用 Goal 的完全访问权限；真实执行尚未结束时仍显示中断过程，不把未持久化成功的停止伪装成成功。

## 配置、数据与安全边界

- 不要求重建已有配置或会话，不迁移会话正文或凭据存储；本次开发验证未读取或修改真实用户配置和 session。自动化测试不代表所有私有数据、模型来源或部署环境都已验证。
- 临时代理和凭据不写入 Git/npm 全局配置、浏览器存储或更新 journal。更新状态、锁、journal、候选和旧依赖保存在源码安装自身的私有 Git 状态目录中，不写进 Dashboard 打开的用户项目。
- 仅支持普通独立官方 HTTPS clone；worktree、子模块、符号链接及危险 Git 配置保守拒绝。只有登记的 Dashboard 参与租约保护，其他 CLI/TUI 仍须用户在更新前关闭。
- 旧服务退出后的切换或重启失败会保留备份、journal 和锁，提示人工恢复，不自动回滚或盲目重试。应先关闭相关进程、核对 journal 阶段与实际源码/依赖位置，不要直接删锁、reset 或 clean。备份清理由用户确认后手动进行。详细步骤见 [源码更新说明](../deployment/source-self-update.md)。

## 升级与产物位置

需要 Node.js 22.18 或更高。从尚无按钮的旧版首次升级到 2.0.29，仍须在源码安装根目录手动执行：

```sh
git pull --ff-only
npm ci
npm run verify:install
npm link
ant-code --version
```

版本应显示 `2.0.29`。退出旧的 CLI/TUI/Dashboard，再启动 Dashboard 并刷新浏览器；仅拉取磁盘代码不会让旧进程获得按钮。完成本次升级后，符合上述条件的安装才可用按钮进行后续更新。已正确链接的同一源码安装在后续按钮更新时不必再次 link。

本次不更新 Windows 成品包或 TaxaMask 内嵌副本，也不发布 npm 私有包。没有新增成品下载包；源码更新的状态和恢复材料留在该安装的私有 Git 状态目录，已有项目、配置和会话可继续使用。
