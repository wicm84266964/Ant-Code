# Ant Code v2.0.28：模型列表可设上下文，旧子智能体名字并入现有角色

发布日期：2026-10-21

本版本把上下文上限加回设置里的模型列表，并撤下两个不再单独出现的子智能体。这是兼容性更新。候选阶段不提前声称 CI、tag 或 GitHub Release 已经完成。

## 对用户工作流的直接变化

- 设置里的每个模型都可以填写上下文上限。离开输入框或按回车即保存。留空表示不单独限制，压缩仍按本地预算，默认 20 万。
- 目录如果报了长度，只补空白项。已经保存的数字在刷新目录时保留。想改用目录报的长度，先清空再刷新。
- 任务进行中也可以保存。当前这轮仍用原来的上限，不会报错。下一轮开始后再按新上限压缩。
- `junior` 不再作为独立子智能体出现。旧名字 `junior`、`worker`、`executor` 转到 `code-worker`。没有写范围时仍然不能写文件。
- `readonly-researcher` 不再作为独立子智能体出现。旧名字 `readonly-researcher`、`research`、`researcher` 转到 `web-researcher`。查仓库仍走 `explorer`。

## 配置、数据与安全边界

- 不改变权限模式、凭据存储或会话正文。已有配置和会话可以继续使用。
- 上下文上限写在模型来源所属的配置里。密钥不会因此回显。
- 旧名字只是转到现有角色，不会新增写权限。自动化测试不能代表所有私有研究数据或每一个外部模型供应商都已验证。

## 升级与产物位置

```sh
npm ci
npm run verify:install
npm link
ant-code --version
```

`ant-code --version` 应显示 `2.0.28`。正在运行的 Dashboard 需要重启并刷新浏览器。

## 验证、限制与待完成门禁

- 开发仓已运行上下文窗口、目录刷新和子智能体名字相关的单元测试。候选阶段的正式仓 `verify:release`、CI、tag 和 GitHub Release 完成后才会记入发布记录。
- 已知限制：当前这轮不会中途改用新的上下文上限。最终结论以正式仓同一提交的 CI 和 Release 门禁为准。
