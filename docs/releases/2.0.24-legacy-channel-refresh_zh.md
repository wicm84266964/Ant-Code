# Ant Code v2.0.24：旧渠道刷新不再重复建档

发布日期：2026-10-18

本版本修复从很早版本升级后，刷新已保存的单模型渠道会失败的问题。候选阶段不提前声称 CI、tag 或 GitHub Release 已经完成。

## 对用户工作流的直接变化

- 在设置里刷新一个已经保存的渠道时，目录写回这条渠道原来所属的范围。只保存在当前项目的旧渠道不会再被复制成一条全局同名来源。
- 旧的 `gw-` 渠道如果已经同时出现在项目和全局配置里，打开 Dashboard 时保留先拥有它的那一份，不再因为同名记录整页失败。
- 两个不同地址仍然不能共用同一个自选路线名。

## 配置、数据与安全边界

- 不改变权限模式、凭据存储或新路线名的保存方式。已有会话可以继续打开。
- 刷新会更新这条渠道本次读到的模型目录。密钥仍留在原来的凭据记录里，不会在界面回显。
- 自动化测试不能代表所有私有研究数据或每一个外部模型供应商都已验证。

## 升级与产物位置

```sh
npm ci
npm run verify:install
npm link
ant-code --version
```

`ant-code --version` 应显示 `2.0.24`。正在运行的 Dashboard 需要重启并刷新浏览器。

## 验证、限制与待完成门禁

- 开发仓已运行配置解析和刷新范围的单元测试。候选阶段的正式仓 `verify:release`、CI、tag 和 GitHub Release 完成后才会记入发布记录。
- 已知限制：如果两个不同地址在升级前被写成了同一个自选路线名，刷新仍会拒绝，需要改成不同路线名。最终结论以正式仓同一提交的 CI 和 Release 门禁为准。
