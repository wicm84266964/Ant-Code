# Ant Code v2.0.31：空闲 Dashboard 可以继续源码更新

发布日期：2026-10-27

本版本修正 Dashboard 源码更新在没有活动任务时仍被拒绝的问题。你正在使用的窗口可以留着，确认后自动重启。这是兼容性修复。候选阶段不表示正式仓 CI、tag 或 GitHub Release 已经完成。

## 对用户工作流的直接变化

- 当前这个 Dashboard 可以保持打开。确认更新后，它会在原项目、原端口重启。
- 同一份源码安装里，另一个没有任务的 Dashboard 会在更新时关闭，不必先手动退出。
- 另一个窗口里还有运行、排队、待确认或状态不确定的任务时，更新仍然停止，不会自动取消那些任务。
- 开着窗口本身的标题生成、后台快照、定时清理和活动检查超时，不再被当成必须先处理的工作。
- 已经结束、只是还没把结果交回会话的任务组，不再单独阻止更新。
- 界面会说明当前窗口可以留着。无法确认另一扇窗口是否空闲时，仍提示先关闭那一扇。

## 配置、数据与安全边界

- 不新增配置字段，不重建会话、凭据或用户项目文件。更新状态仍留在源码安装自身的私有 Git 状态目录。
- 关闭另一扇空闲 Dashboard 只接受本机回环上的同一次安装登记。有任务或无法确认空闲的窗口不会被关掉。
- 源码有修改、上游不能安全快进、真实活动工作、损坏或未结束的任务记录，仍然阻止更新，不会自动清理或回滚。
- 其他 CLI/TUI 没有登记，更新流程关不掉它们，开始前仍须自行关闭。
- 自动化测试不能代表所有私有研究数据、外部模型供应商或部署环境都已验证。

## 升级与产物位置

需要 Node.js 22.18 或更高。正在运行的 2.0.29 或 2.0.30 如果因为上述空闲误判拒绝按钮，这一次仍须在源码安装根目录手动升级：

```sh
git pull --ff-only
npm ci
npm run verify:install
npm link
ant-code --version
```

版本应显示 `2.0.31`。退出旧的 CLI、TUI 和 Dashboard 再启动。只更新磁盘代码不会改变已经打开的旧进程。完成本次升级后，符合条件的安装可用按钮进行后续更新；已正确链接的同一源码安装不必再次 link。

本次不更新 Windows 成品包或 TaxaMask 内嵌副本，也不发布 npm 私有包。没有新增成品下载包。
