# Dashboard 源码版更新

Dashboard 左上角显示当前进程启动时的产品版本，旁边提供“更新”入口。此流程仅面向独立官方源码安装，不更新 Windows 成品包或 TaxaMask 内嵌副本。npm 包保持私有，不执行 publish。

如果正在使用尚无更新按钮的旧版，首次升级到 2.0.29 仍须手动拉取源码，执行 `npm ci`、`npm link`，退出旧进程再重启 Dashboard 并刷新页面。运行中的旧版不会自动获得按钮；完成这次升级后，符合条件的源码安装才可用按钮进行后续更新。

## 使用流程

1. 保存代码，处理未发送的输入、附件及待确认操作。当前这个 Dashboard 可以留着，确认后会自动重启。另一个没有任务的 Dashboard 会在更新时关闭；有任务的另一个窗口，以及其他 CLI/TUI，仍须先处理或关闭。
2. 打开左上角更新窗口，检查版本。默认先发现代理，不会直接访问 GitHub。按顺序读取应用配置、代理环境变量、Git/npm 配置及 Windows 静态系统代理中的真实地址和端口；不扫描本机端口，不假定 7890 等常用端口。
3. 自动发现无可用配置时，可填写仅本次使用的 HTTP/HTTPS 代理。SOCKS、PAC/WPAD 暂不执行；可改填代理软件提供的 HTTP 混合端口。不要把 PAC 脚本 URL 当代理地址。
4. 只有主动选择“仅本次直连”才绕过代理。选中的代理失败会停止，不会静默改为直连、换镜像或关闭 TLS 校验。Git 与 npm 使用同一条明确路由；临时代理及凭据不写入 Git/npm 全局配置、浏览器存储或更新日志。
5. 检查结果展示当前分支及目标 commit，确认后准备候选依赖；准备成功并确认没有活动工作后才关闭旧服务，更新源码并在原项目、原端口自动重启。
6. 浏览器在同源重新获取认证，并核验任务、目标 commit 和新进程身份后刷新。单纯端口恢复或版本号变化不算更新成功。

## 源码保护与支持边界

- 最新代码指当前分支已配置的官方 HTTPS upstream tip，不擅自切换分支/标签。没有上游、detached HEAD、本地修改、未跟踪文件、分叉/领先上游、Git 操作进行中或不支持的布局会阻止更新。
- 不执行强制覆盖、自动 stash、reset、clean 或自动 Git 回滚，不替用户设置 origin。任何未配置受支持上游的源码检出（包括离线检出）都应拒绝更新，不因环境不同而绕过保护。
- 更新根是实际运行的 Ant Code 源码安装根，不是 Dashboard 打开的用户项目。已正确链接到该源码目录的全局命令无需再次 link；更新器不会把全局入口切到另一份安装。
- 当前仅支持普通独立官方 HTTPS clone；复杂 worktree、子模块、符号链接、危险 Git 执行配置等保守拒绝。只有参与登记的 Dashboard 实例可被租约识别，其他 CLI/TUI 仍须用户主动关闭。
- 候选目录执行锁定的 `npm ci --ignore-scripts --no-audit --no-fund`，不自动开启依赖脚本、不修改用户 registry 或降低 TLS；依赖/Node engine/启动检查失败时保留旧服务。启动预检会加载实际 CLI 的静态导入，但不是执行不可信代码的操作系统沙箱。
- 维护门不自动终止正在运行、排队、等待确认、隔离或状态不确定的工作；请等待完成再试。
- 原生 Node/npm 布局必须可找到可信 `npm-cli.js`。使用 Node 执行它，不通过 shell 拼接命令或执行 `npm.cmd`。

## 失败与恢复

候选准备失败不切换源码或原依赖。旧服务退出后的切换/启动失败会保留安装仓库私有 Git 状态目录 `.git/ant-source-update/` 下对应更新任务的 journal、候选与旧依赖，并显示需要人工恢复；不会谎报已恢复旧版本。这些状态不写入用户项目，也不记录环境变量或凭据。

先关闭所有使用该源码安装的进程，再检查 journal 中的阶段、当前 `git rev-parse HEAD` 和依赖目录实际位置。不要盲目删锁重试，也不要直接 reset/clean。依赖交换分步记录 intent/completion，发生断电或文件占用时应依据实际完成步骤处理，必要时在另一目录重新克隆干净源码，继续使用原项目/用户配置。备份目录不自动删除，确认新版本稳定后再人工清理属于该更新任务的备份。

浏览器不能连接新服务时会超时给出提示；关闭页面不代表更新任务取消。更新不会自动提权，也不保证断电后自动继续执行。

## 验证与限制

Windows 隔离临时 Git clone 中的真实产品 CLI 原端口重启测试已通过 3/3，另有候选与日志检查、异步状态快照保护、计划任务竞态和旧服务关闭后链路的自动化覆盖。产品 Dashboard 已启用严格原端口重启能力；该能力不绕过每份安装的仓库布局、上游、租约与活动检查，不符合条件仍拒绝更新，未接入更新器的服务仍不可用。

早期曾有一次产品重启记录 `RESTART_EXITED`，当时子进程诊断不足，根因尚未定位；后续带受限诊断的检查未复现，不能据此宣称间歇风险已消除。

上述本地测试不等同于真实官方在线升级，也不表示候选已正式发布。POSIX 的进程组、权限、rename/fsync 与完整更新重启、真实公网升级、目标像素视觉、真 TTY 和全局安装 smoke 仍未验收。截图文件或浏览器行为测试不能单独视为像素验收通过。源码更新不替代发布前门禁，也不会发布、推送或修改产品版本号；每个候选仍须在正式仓同一提交上完成 CI 与正式复验。
